Phase 1: Recommendation Engine & Algorithm Fixes (High Priority)

1. Implement True TF-IDF (Fix P3.3)

Currently, src/lib/recommendation.ts only computes Term Frequency (tf). To fulfill the synopsis specification:

  • Compute Document Frequency df(t) for every term across the entire material catalog.
  • Compute Inverse Document Frequency: idf(t) = log((N + 1) / (df(t) + 1)) + 1, where N is total materials.
  • Calculate the TF-IDF weight vector for each document: tfidf(t, d) = tf(t, d) * idf(t).
2. Implement Actual Collaborative Filtering (Fix P3.4)

The synopsis specifies collaborative filtering from the Rating DB.

  • Build a user-item rating matrix from the ratings table.
  • Implement either User-Based Collaborative Filtering (Pearson correlation / Cosine similarity between users) or Item-Based Collaborative Filtering (similarity between materials based on co-ratings).
  • Replace the static rating_count / 25 popularity proxy with the genuine collaborative prediction score.
3. Migrate Recommendation Pipeline to Server Function (Fix P3 Execution)

Currently, recommendations are calculated inside the student's browser via React useMemo. Move this calculation entirely to a server function (e.g. generateUserRecommendations in src/lib/activity.functions.ts) so the client only requests recommendations and the server queries the database, executes TF-IDF + Collaborative Filtering, persists to recommendations, and returns the result.

Phase 2: Search Architecture & Data Flow (Medium Priority)

4. Server-Side Database Full-Text Search (Fix P2)

Currently, search.tsx downloads the entire catalog and filters in memory with .includes(). To follow DFD Level 1:

  • Create a dedicated server function / backend endpoint for search: searchMaterials({ query, subjectId, type, page }).
  • Utilize PostgreSQL full-text search (to_tsvector / websearch_to_tsquery on title || ' ' || description) or MongoDB $text index.
  • Return paginated results from the database to the client.
